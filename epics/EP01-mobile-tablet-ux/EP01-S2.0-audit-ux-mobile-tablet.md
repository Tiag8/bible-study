# EP01-S2.0 — Auditoria UX/UI completa mobile/tablet

## Objetivo

Auditar todas as 5 telas do app em viewport mobile/tablet, gerar `docs/ux/mobile-tablet-audit.md` com findings priorizados (P0 já resolvidos em S1.0, foco em P1/P2). NÃO implementa correções — gera roadmap.

## User Story

Como product owner do Bible Study, quero um audit estruturado de UX mobile/tablet para decidir quais P1/P2 valem virar story futura, evitando refactor especulativo.

## Critérios de Aceitação

### AC1 — Audit cobre as 2 telas críticas (Dashboard + Editor)

- [ ] `/` (Dashboard) — Sidebar, TopBar, BookGrid, ChapterView, BacklogPanel
- [ ] `/estudo/[id]` (Editor) — Tiptap editor, BubbleMenu, SlashMenu, ReferencesSidebar

Cada tela auditada nos 3 viewports: 360 (mobile), 768 (tablet portrait), 1024 (tablet landscape / small desktop).

**Telas adiadas para audit futuro** (se houver demanda): `/grafo`, `/settings`, `/login`. São secundárias na jornada principal de estudo. Cobertura completa fica como EP02 se P1/P2 dessas telas surgirem.

### AC2 — Findings categorizados

Cada finding tem:

- **ID** — F1, F2, F3...
- **Tela** — uma das 5
- **Viewport** — 360 / 768 / 1024 ou "todos"
- **Severidade** — P1 (alta — bloqueia uso) / P2 (média — degrada experiência) / P3 (baixa — polimento)
- **Problema** — 1-2 linhas concretas (o que dá errado, não opinião)
- **Evidência** — screenshot ou descrição reproduzível
- **Sugestão** — 1 linha sobre direção de fix (não solução completa)
- **Effort estimate** — XS/S/M/L (XS < 1h, S < 4h, M < 8h, L > 8h)

### AC3 — Dimensões cobertas

Pelo menos 1 finding (ou "OK" se nada problemático) por dimensão:

- [ ] **Touch targets** (mínimo 44x44px em iOS HIG, 48x48 em Material)
- [ ] **Tipografia** (font-size mínimo 16px para evitar zoom auto iOS, line-height ≥ 1.4, contrast WCAG AA)
- [ ] **Navegação** (sidebar fixa vs drawer, bottom-nav viability)
- [ ] **Editor mobile** (teclado virtual oclui conteúdo? scroll funciona?)
- [ ] **Grafo touch** (pan/zoom/tap funcionam? canvas redimensiona?)
- [ ] **Performance** (impressão subjetiva — sem medição rigorosa, só notas se algo está visivelmente lento)

### AC4 — Output: `docs/ux/mobile-tablet-audit.md`

Arquivo com:

- Sumário (quantos findings por severidade)
- Tabela de findings (todas as colunas do AC2)
- Recomendação de roadmap (quais 3-5 P1 priorizados para próximo epic)
- Out of scope explícito (P3 listados mas marcados como "não vale story dedicada agora")

## Out of Scope

- Implementação de qualquer fix (tudo audit-only)
- Medição rigorosa de Lighthouse / Web Vitals (só impressão subjetiva)
- Análise de acessibilidade screen-reader (story futura dedicada)
- Redesign visual

## Pré-requisitos

- [x] EP01-S1.0 entregue (P0 resolvidos — audit avalia estado pós-fix, não pré-fix)
- App rodando local (`npm run dev`) ou em deploy estável

## Definition of Done

- [ ] `docs/ux/mobile-tablet-audit.md` criado
- [ ] AC1-AC4 cumpridos
- [ ] Mínimo 5 findings (entre P1/P2/P3) — escopo reduzido para 2 telas, então mínimo proporcional. Se < 5, audit foi superficial; reabrir
- [ ] @po valida que roadmap recomendado é acionável (cada P1 priorizado pode virar story sem ambiguidade)
- [ ] Commit `docs(ux): add mobile-tablet audit`
