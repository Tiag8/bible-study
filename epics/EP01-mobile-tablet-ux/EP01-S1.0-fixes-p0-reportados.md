# EP01-S1.0 — Resolver 3 problemas P0 reportados

## Objetivo

Tornar o app utilizável em iPad/iPhone resolvendo as 3 issues reportadas em uso real (2026-05-04). Sem regressão desktop.

## User Story

Como usuário do Bible Study no tablet, quero poder editar estudos sem o Chrome interferir, ler conteúdo sem pan horizontal e usar o editor sem o emoji picker, para concluir uma sessão de estudo de Bíblia sem fricção.

## Critérios de Aceitação

### AC1 — Conflito Tiptap × Chrome edit menu resolvido

- [ ] Reproduzir cenário em iPad (Safari) e Android (Chrome): selecionar texto no editor não dispara menu nativo do Chrome simultaneamente com BubbleMenu do Tiptap.
- [ ] Investigação documentada em comentário do PR ou no próprio commit (root cause: provavelmente atributos de `contenteditable` / `inputmode` / falta de `editorProps.attributes`).
- [ ] Solução aplicada em `src/components/Editor/index.tsx` ou config do Tiptap (preferir solução declarativa via `editorProps`, evitar hacks CSS globais).
- [ ] **Timebox**: se solução limpa não emergir em ~60min de investigação, aplicar workaround documentado (ex: CSS `-webkit-user-modify`) e abrir nota em `docs/ux/mobile-tablet-audit.md` (S2.0) ou TODO inline no commit, não bloquear S1.0 inteira por isso.
- [ ] Smoke test manual: selecionar texto → BubbleMenu aparece → ações (bold, italic, link) funcionam sem interferência do Chrome.

### AC2 — Layout responsivo viewport < 1024px

- [ ] Página `/` (Dashboard) renderiza sem pan horizontal em 360px (mobile) e 768px (tablet).
- [ ] Página `/estudo/[id]` (Editor) renderiza com fluxo natural de leitura — sidebar de referências colapsa ou esconde em < 1024px (não tenta caber lado-a-lado).
- [ ] Página `/grafo` é minimamente utilizável em mobile (canvas não corta, controles acessíveis) — pinch-zoom é P2, fora desta story.
- [ ] DevTools responsive: 360 / 768 / 1024 sem overflow horizontal nas 3 páginas críticas.
- [ ] Desktop (≥ 1024px) sem regressão visual.

### AC3 — Emoji picker removido do editor

- [ ] Componente `src/components/Editor/EmojiMenu.tsx` removido (ou marcado deprecated e não montado).
- [ ] Hook `src/components/Editor/useEmojiSuggestion.ts` removido (ou desativado — preferir remoção limpa).
- [ ] `lib/emoji-data.ts` removido se não for usado em outro lugar (verificar via grep antes).
- [ ] Imports e uso em `src/components/Editor/index.tsx` (linhas 21, 22, 235, 304) removidos.
- [ ] SlashMenu não oferece comando de emoji.
- [ ] BubbleMenu toolbar não tem botão de emoji (verificar `BubbleMenuToolbar.tsx`).
- [ ] Build PASS após remoção (`npm run build`).
- [ ] Bundle size reduz (verificar `.next/` antes/depois — esperar redução de pelo menos `emoji-data.ts`).

## Risks

- **R1**: Conflito Tiptap × Chrome pode exigir solução parcial. Mitigação: documentar limitação no commit message + criar issue para aprofundar se persistir.
- **R2**: Remover emoji pode quebrar studies antigos com emojis salvos no JSON do Tiptap. Mitigação: emojis são chars Unicode normais — Tiptap renderiza como texto, não depende do menu para exibir. Testar abrindo um study existente após remoção.

## Notas técnicas

- Tiptap `editorProps.attributes` aceita `inputmode`, `autocorrect`, `autocapitalize` — investigar primeiro.
- CSS `-webkit-user-modify: read-write-plaintext-only` desabilita edit menu nativo em alguns casos — usar como último recurso e documentar.
- Tailwind breakpoints default: `sm: 640px`, `md: 768px`, `lg: 1024px`, `xl: 1280px`. Usar `md:` e `lg:` para mobile/tablet/desktop.
